# ผังดวงอาชีพ

แบบสำรวจความสนใจด้านเทคโนโลยีและอาชีพดิจิทัล · ชุดคำถามที่ 3 (Level 3)
หลักสูตรเทคโนโลยีสารสนเทศ มทร.ล้านนา ลำปาง · กิจกรรม "แม่หมอ VR"

ตอบ 6 ข้อ **ด้วยการชูนิ้วหน้ากล้อง** แล้วอ่านผลเป็นผังดวงหกแกน
ที่บอกว่าผู้ตอบเอนไปทางสายงานไอทีใด

**เล่นได้ที่ https://maemor-game.vercel.app**
โหมดบูธ: https://maemor-game.vercel.app/?mode=kiosk

---

## เริ่มใช้งาน

```bash
npm install          # ครั้งเดียว
npm run dev          # เปิด http://localhost:4173
npm run check        # สร้างไฟล์ใหม่ + ตรวจทุกอย่าง
npm run manual       # สร้างคู่มือ PDF
npm run shots        # ถ่ายภาพทุกฉากทั้งจอคอมและมือถือ ไว้ดูผลการจัดหน้า
```

> กล้องทำงานเฉพาะบน `https` หรือ `localhost` เท่านั้น — เป็นข้อบังคับของเบราว์เซอร์
> เปิดจากไฟล์ตรง ๆ (`file://`) จะใช้กล้องไม่ได้

## นำขึ้นออนไลน์

โปรเจกต์ผูกกับ GitHub แล้ว — **push ขึ้น `main` แล้ว Vercel จะ deploy ให้เอง**

```bash
git add . && git commit -m "อธิบายสิ่งที่แก้" && git push
```

`vercel.json` ตั้งค่าไว้แล้ว: build ด้วย `npm run build` แล้วเสิร์ฟจาก `app/public`

> หลัง deploy ทุกครั้ง เปิดเว็บบนเครื่องบูธแล้ว**โหลดหน้าใหม่สองครั้ง**
> ครั้งแรก service worker จะดึงชุดใหม่มาเก็บ ครั้งที่สองจึงเริ่มใช้ชุดใหม่

## สร้างป้าย QR สำหรับพิมพ์

```bash
npm run qr -- https://maemor-game.vercel.app
```

ได้ไฟล์ใน `dist/qr/`

| ไฟล์ | ใช้ทำอะไร |
|---|---|
| `qr.svg` | เวกเตอร์ ขยายพิมพ์ใหญ่แค่ไหนก็คม |
| `qr.png` | 2048px สำหรับป้ายไวนิลหรือสไลด์ |
| `poster.html` | หน้า A4 เปิดในเบราว์เซอร์แล้วสั่งพิมพ์ได้เลย |

QR ใช้ระดับแก้ไขความผิดพลาด H (สูงสุด) เพราะป้ายที่บูธมักโดนแสงสะท้อนและถูกสแกนจากมุมเอียง
ทุกครั้งที่สร้าง สคริปต์จะ**ถอดรหัสกลับมาตรวจ**ด้วยไลบรารีคนละตัว ถ้าไม่ตรงจะหยุดทันที
QR ที่พิมพ์ลงป้ายไวนิลแล้วสแกนไม่ติดคือความผิดพลาดที่แก้ไม่ได้หน้างาน

## ทิศทางการออกแบบ

กริดเชิงเทคนิคบนพื้นฟ้าที่มีแสงหักเห ตัวอักษรแบ่งสองระดับชัดเจนโดยไม่มีขนาดกลาง ๆ ให้ลังเล
และแถบข้อมูลสถานะที่เดินจริงอยู่ด้านล่าง อ้างอิงภาษาออกแบบจาก [haoqi.design](https://haoqi.design)

| ส่วน | ใช้อะไร |
|---|---|
| พาดหัว | Anuphan 700 · ระยะอักษรติดลบ · ตัวใหญ่มาก |
| เนื้อหา | Anuphan 400/500 |
| ข้อมูลกำกับ ตัวเลข | IBM Plex Mono · ตัวพิมพ์ใหญ่ · ระยะอักษรกว้าง |
| สีเน้น | น้ำเงิน `#2E6FDF` เพียงสีเดียว |

องค์ประกอบที่ทำให้หน้ารู้สึกเป็นเครื่องมือที่กำลังทำงาน ไม่ใช่ภาพนิ่ง

- **กริดกากบาท** — วาดเป็น SVG จาก [motion.js](app/public/src/motion.js) เพราะ CSS วางกากบาท
  ให้ตรงจุดตัดพอดีทุกขนาดจอไม่ได้
- **แถบสถานะล่าง** — เวลาที่เดินจริงพร้อมเขตเวลา พิกัดเมาส์ และสถานะเครือข่าย
- **เคอร์เซอร์กำหนดเอง** — จุดตามติดกับวงแหวนที่ตามช้ากว่า วงแหวนโตขึ้นเมื่ออยู่เหนือสิ่งที่กดได้
- **แสงและก้อนเบลอ** — CSS ล้วน ไม่มีไฟล์ภาพให้โหลดเพิ่มแม้แต่ไบต์เดียว ขยับตามเมาส์คนละอัตราเพื่อให้เกิดความลึก
- **พาดหัวเผยทีละบรรทัด** — แบ่งตาม `<br>` ที่เขียนไว้ ไม่ใช่ตัดตามตำแหน่งบรรทัดจริง
  วิธีหลังต้องรื้อเนื้อหาเป็นคำ ๆ ก่อน ซึ่งทำลายตัวเน้นสีและจุดขึ้นบรรทัดทิ้ง

ทุกอย่างในชั้นนี้เป็นของประดับ ถ้าไม่ทำงานแอปยังใช้ได้ครบ และปิดทั้งหมดเมื่อระบบตั้งค่าลดการเคลื่อนไหว

**แผ่นผังดวงยังเป็นตัวเอกเหมือนเดิม** เพราะมันผูกกับเนื้อหาจริง ไม่ใช่ของตกแต่งที่เปลี่ยนตามธีมได้

## การเลือกคำตอบด้วยการชูนิ้ว

ชูนิ้วกี่นิ้ว = เลือกข้อนั้น ค้างท่าเดิมไว้ราว 1.1 วินาทีจึงยืนยัน
ข้อสุดท้ายมีหกตัวเลือก จึงต้องใช้สองมือ (ระบบรับสองมือและนับรวมกัน)

ทำงานอย่างไร — [hands.js](app/public/src/hands.js)

1. MediaPipe Hand Landmarker หาจุดข้อต่อ 21 จุดต่อมือหนึ่งข้าง
2. วัด**มุมที่ข้อกลางนิ้ว** เพื่อตัดสินว่านิ้วใดเหยียด ใช้มุมแทนการเทียบความสูง
   เพราะมุมไม่เปลี่ยนตามการเอียงหรือหมุนมือ ผู้เล่นจึงไม่ต้องยกมือตั้งฉากกับกล้อง
3. นิ้วโป้งตรวจสองเงื่อนไข: ข้อไม่งอ **และ** กางออกจากฝ่ามือจริง
   ถ้าดูแค่มุม นิ้วโป้งที่พับทับฝ่ามือจะยังนับว่าเหยียดอยู่
4. ต้องค้างท่าเดิมให้ครบเวลาจึงนับ มือหลุดเฟรมชั่วครู่มีเวลาผ่อนผัน 400 มิลลิวินาที

โครงมือที่วาดทับภาพไม่ได้มีไว้ดูสวย — **ปลายนิ้วที่ระบบนับว่าเหยียดจะเป็นจุดสีแดง**
เวลานับผิดจะเห็นทันทีว่าเป็นเพราะนิ้วไหน ซึ่งทำให้ผู้เล่นแก้ท่าเองได้

**แตะหน้าจอเลือกคำตอบได้เสมอ** ทั้งระหว่างที่โมเดลกำลังโหลด เมื่อไม่ได้รับอนุญาตให้ใช้กล้อง
และเมื่อแสงไม่เอื้อ — ไม่มีจังหวะไหนที่ผู้เล่นถูกบังคับให้รอ

### ขนาดที่ต้องแลกมา

| | ขนาด | โหลดเมื่อไร |
|---|---|---|
| ตัวแอป | 333 KB | ตอนเปิดครั้งแรก เล่นได้ทันที |
| โมเดลนับนิ้ว | 19 MB (≈ 8.4 MB หลังบีบอัด) | ตอนเข้าหน้าคำถามครั้งแรก |

โมเดลถูกโหลดแยกและมีแถบบอกความคืบหน้า เพราะบน WiFi งานนิทรรศการที่คนเยอะ
การโหลดเงียบ ๆ จะทำให้ผู้ใช้เห็นแค่หน้าจอค้างโดยไม่รู้ว่าต้องรออีกนานเท่าไร

หลังโหลดครบครั้งแรก service worker เก็บไว้ในเครื่อง ใช้กล้องแบบออฟไลน์ได้เลย

## ความเป็นส่วนตัว

- ไม่เก็บชื่อ นามสกุล โรงเรียน หรือเบอร์โทร
- บันทึกเฉพาะ วันที่ · เวลา · หมายเลขรอบที่ระบบสร้างเอง · ผลการสำรวจ · เวลาที่ใช้
- เก็บใน `localStorage` ของเครื่องนั้นเท่านั้น ไม่มีเซิร์ฟเวอร์ ไม่มีการส่งออก
- **ภาพจากกล้องถูกประมวลผลในเครื่องทั้งหมด** โมเดลรันบน WebAssembly ในเบราว์เซอร์
  ไม่มีเฟรมใดถูกอัปโหลด บันทึก หรือส่งออกไปที่ใด

เจ้าหน้าที่ดาวน์โหลดบันทึกเป็น CSV ได้จากแผง "บันทึกผู้เข้าร่วม"

### แก้คำถาม

แก้ [app/public/src/data.js](app/public/src/data.js) ที่เดียว แล้วรัน `npm run check`
จากนั้น `npm run manual` เพื่อให้คู่มือตรงกับแอป — คู่มือดึงคำถามและเกณฑ์คะแนนจากไฟล์เดียวกัน

`check-balance.mjs` จะไล่ทุกเส้นทางคำตอบที่เป็นไปได้ (ตอนนี้ 12,000 เส้นทาง)
แล้วรายงานว่าแต่ละสายมีโอกาสออกกี่เปอร์เซ็นต์ ถ้าสายไหนต่ำผิดปกติแปลว่าคำถามเอียง

ปัจจุบันอยู่ในช่วง **13.8–19.4%** (อุดมคติคือ 16.7%)

คะแนนถูก normalize ด้วยเพดานของแต่ละแกนก่อนจัดอันดับเสมอ ดังนั้นการเพิ่มตัวเลือกที่ให้คะแนนสายใดสายหนึ่ง
จะไม่ทำให้สายนั้นได้เปรียบโดยอัตโนมัติ

> ถ้าเพิ่มข้อที่มีมากกว่า 6 ตัวเลือก ต้องทบทวนก่อน — คนชูนิ้วได้สูงสุด 10 นิ้ว
> แต่เกิน 6 เริ่มนับยากและช้าที่บูธ

## หมายเหตุด้านเทคนิค

**ไม่มีขั้นตอน build ของ JavaScript โดยตั้งใจ** — เป็น ES modules ล้วน เสิร์ฟตรง
บูธนี้ต้องยังใช้งานได้ในอีกหลายปีข้างหน้า การไม่มี bundler แปลว่าไม่มีอะไรให้ผุ
`npm run build` ทำแค่สองอย่าง: สร้างไอคอน PNG และสร้างรายการไฟล์ใน `sw.js` ใหม่

**`sw.js` มีเลขรุ่นที่คำนวณจากเนื้อไฟล์จริง** พอมีไฟล์ไหนเปลี่ยน แคชเก่าจะถูกลบทั้งชุด
เครื่องที่ติดตั้งไว้แล้วจึงไม่ค้างอยู่กับรุ่นเก่าโดยไม่มีใครรู้ตัว

**คู่มือ PDF เรนเดอร์ด้วย Chrome ที่ติดตั้งอยู่แล้ว** ผ่าน `--print-to-pdf` จึงไม่ต้องโหลด Chromium เพิ่ม
ฟอนต์ฝังเป็น data URI เพราะ Chrome ปฏิเสธการโหลดฟอนต์ข้ามไฟล์เมื่อเปิดผ่าน `file://`

**เปลี่ยนฟอนต์** ด้วย `node build/fetch-fonts.mjs "ชื่อตระกูล:wght@400;700"`
สคริปต์จะเก็บเฉพาะชุดอักษรไทยกับละติน แล้วเขียน `src/fonts.css` ให้ใหม่ทั้งไฟล์
อย่าลืมแก้ชื่อตระกูลใน `styles.css` และในรายการ `FONTS` ของ `build/make-manual.mjs` ตามด้วย
