# ผังดวงอาชีพ

แบบสำรวจความสนใจด้านเทคโนโลยีและอาชีพดิจิทัล · ชุดคำถามที่ 3 (Level 3)
หลักสูตรเทคโนโลยีสารสนเทศ มทร.ล้านนา ลำปาง · กิจกรรม "แม่หมอ VR"

ตอบ 6 ข้อ **ด้วยการชูนิ้วหน้ากล้อง** แล้วอ่านผลเป็นผังดวงหกแกน

**เล่นได้ที่ https://maemor-game.vercel.app**
โหมดบูธ: https://maemor-game.vercel.app/?mode=kiosk

---

## เริ่มใช้งาน

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # สร้าง out/ + service worker
npm run verify   # ตรวจสมดุลคะแนน + ตรรกะการนับนิ้ว
npm run shots    # เล่นจนจบจริงในเบราว์เซอร์ แล้วถ่ายภาพทุกฉาก
npm run manual   # คู่มือ PDF
npm run qr -- https://maemor-game.vercel.app
```

> กล้องทำงานเฉพาะบน `https` หรือ `localhost` — เป็นข้อบังคับของเบราว์เซอร์

## นำขึ้นออนไลน์

ผูกกับ GitHub แล้ว **push ขึ้น `main` แล้ว Vercel deploy ให้เอง**

```bash
git add . && git commit -m "อธิบายสิ่งที่แก้" && git push
```

> หลัง deploy เปิดเว็บบนเครื่องบูธแล้ว**โหลดหน้าใหม่สองครั้ง**
> ครั้งแรก service worker ดึงชุดใหม่มาเก็บ ครั้งที่สองจึงเริ่มใช้

## สแตกและเหตุผล

**Next.js (App Router) + React Three Fiber** ตั้งค่าเป็น `output: "export"`
แอปนี้ไม่มีตรรกะฝั่งเซิร์ฟเวอร์เลย จึงได้ไฟล์สแตติกล้วนใน `out/`
เสิร์ฟเร็วที่สุด ไม่ต้องมีเซิร์ฟเวอร์คอยรัน และ service worker รู้ชื่อไฟล์ทุกไฟล์หลัง build

> ข้อแลกเปลี่ยน: `headers()` ใน `next.config.mjs` ใช้ไม่ได้ในโหมด export
> จึงย้ายไปตั้งใน [vercel.json](vercel.json) แทน

## ทิศทางการออกแบบ

อ้างอิงภาษาออกแบบจาก [haoqi.design](https://haoqi.design) — เอา*ระบบ*มาใช้ ไม่ได้ลอกสินทรัพย์ของเขา
กริดเชิงเทคนิคพร้อมกากบาทตรงจุดตัด · วัตถุ 3D มันวาวลอยหลังเนื้อหา ·
แถบข้อมูลสถานะที่ตัวเลขเดินจริง · เคอร์เซอร์กำหนดเอง · สวิตช์แบบ `theme[day]`

### ตัวอักษร — บทเรียนที่แลกมาด้วยรอบที่อ่านไม่ออก

รอบก่อนใช้ Anuphan แล้วเอาภาษาไทยไปใส่กฎของ mono ผลคืออ่านยากมาก สาเหตุมีสี่ข้อ

| ที่ทำผิด | ทำไมพัง |
|---|---|
| `text-transform: uppercase` | ไทยไม่มีตัวพิมพ์ใหญ่ แต่คำสั่งนี้ทำให้เบราว์เซอร์จัดระยะผิด |
| `letter-spacing` บนข้อความไทย | ดึงสระให้หลุดจากพยัญชนะที่มันเกาะอยู่ |
| ขนาด 12px | ไทยมีสระบนล่างสองชั้น ต้องใหญ่กว่าละตินเสมอ |
| `line-height: 1.06` บนพาดหัว | สระบนชนสระล่างของบรรทัดถัดไป |

กฎที่ใช้อยู่ตอนนี้

- **IBM Plex Sans Thai** ทั้งหมด (400/500/600/700) คู่กับ **IBM Plex Mono** — ตระกูลเดียวกัน เข้าชุดกันโดยธรรมชาติ
- **mono ใช้กับตัวเลขและอังกฤษเท่านั้น** ป้ายกำกับภาษาไทยใช้คลาส `.tag` ซึ่งเป็นตัวตรง ไม่ยืดระยะ ไม่แปลงตัวพิมพ์
- ขนาดเล็กสุดในหน้าจอคือ **14px** เนื้อหา **17px** line-height **1.75**

### กราฟฟิก 3D

[Scene3D.jsx](src/components/Scene3D.jsx) — วงแหวนหกเหลี่ยมมันวาว รูปทรงเดียวกับแผ่นผังดวง
จึงไม่ใช่ของประดับที่หยิบมาลอย ๆ แต่เป็นสัญลักษณ์ของตัวกิจกรรมเอง

ข้อจำกัดที่ออกแบบเผื่อไว้ตั้งแต่ต้น

- **ไม่ใช้ HDR environment จาก CDN** — `drei` โหลดจากภายนอกซึ่งใช้ออฟไลน์ไม่ได้
  จึงประกอบ environment เองจาก `Lightformer` ในเครื่อง
- **ใช้พลาสติกเป่าลม ไม่ใช่แก้ว** — เคยลอง `MeshTransmissionMaterial` แล้วออกมาดำสนิท
  เพราะวัสดุแก้วต้องมีฉากหลังให้หักเห แต่ environment ที่ประกอบเองมีแค่แผ่นไฟ
- **หยุดเรนเดอร์ทั้งฉากตอนอยู่หน้าคำถาม** เพราะกล้องกับโมเดลนับนิ้วต้องการ GPU ทั้งหมดในจังหวะนั้น
- **จัดวางตามความกว้างจอ** จอแคบวางวัตถุถอยไปด้านหลังตรงกลางและย่อลง ไม่งั้นจะโผล่ครึ่งตัวที่ขอบจอ

## การเลือกคำตอบด้วยการชูนิ้ว

ชูนิ้วกี่นิ้ว = เลือกข้อนั้น ค้างท่าเดิมราว 1.1 วินาทีจึงยืนยัน
ข้อสุดท้ายมีหกตัวเลือก จึงต้องใช้สองมือ (ระบบรับสองมือและนับรวมกัน)

[hands.js](src/lib/hands.js) ทำงานอย่างไร

1. MediaPipe Hand Landmarker หาจุดข้อต่อ 21 จุดต่อมือหนึ่งข้าง
2. วัด**มุมที่ข้อกลางนิ้ว** เพื่อตัดสินว่านิ้วใดเหยียด ใช้มุมแทนการเทียบความสูง
   เพราะมุมไม่เปลี่ยนตามการเอียงหรือหมุนมือ ผู้เล่นจึงไม่ต้องยกมือตั้งฉากกับกล้อง
3. นิ้วโป้งตรวจสองเงื่อนไข: ข้อไม่งอ **และ** กางออกจากฝ่ามือจริง
   ถ้าดูแค่มุม นิ้วโป้งที่พับทับฝ่ามือจะยังนับว่าเหยียดอยู่
4. ต้องค้างท่าเดิมให้ครบเวลาจึงนับ มือหลุดเฟรมชั่วครู่มีเวลาผ่อนผัน 400 มิลลิวินาที

โครงมือที่วาดทับภาพมีหน้าที่จริง — **ปลายนิ้วที่ระบบนับว่าเหยียดจะเป็นจุดสีน้ำเงิน**
เวลานับผิดจะเห็นทันทีว่าเป็นเพราะนิ้วไหน ผู้เล่นจึงแก้ท่าเองได้

**แตะหน้าจอเลือกคำตอบได้เสมอ** ทั้งระหว่างที่โมเดลกำลังโหลด เมื่อไม่ได้รับอนุญาตให้ใช้กล้อง และเมื่อแสงไม่เอื้อ

> `pick()` มีตัวกันการกดซ้ำ 240 มิลลิวินาที เพื่อไม่ให้ท่ามือเดียวถูกนับสองครั้ง
> การกดเร็วกว่านั้นจะถูกทิ้งเงียบ ๆ ซึ่งตั้งใจไว้แบบนั้น

| | โหมดมือถือ (ค่าเริ่มต้น) | โหมดบูธ |

### คีย์ลัด

`1`–`6` เลือกคำตอบ · `Backspace` ย้อนกลับ · `L` แผงบันทึก · `Esc` เริ่มใหม่ · `Space` ข้ามฉากประมวลผล

อ่านจากตำแหน่งปุ่มจริง (`e.code`) ไม่ใช่ตัวอักษรที่พิมพ์ออกมา จึงยังใช้ได้แม้เครื่องค้างโหมดภาษาไทย

## ความเป็นส่วนตัว

- ไม่เก็บชื่อ นามสกุล โรงเรียน หรือเบอร์โทร
- บันทึกเฉพาะ วันที่ · เวลา · หมายเลขรอบที่ระบบสร้างเอง · ผลการสำรวจ · เวลาที่ใช้
- เก็บใน `localStorage` ของเครื่องนั้นเท่านั้น ไม่มีเซิร์ฟเวอร์
- **ภาพจากกล้องถูกประมวลผลในเครื่องทั้งหมด** ไม่มีเฟรมใดถูกอัปโหลดหรือบันทึก

### แก้คำถาม

แก้ [src/lib/data.js](src/lib/data.js) ที่เดียว แล้ว `npm run verify` และ `npm run manual`
คู่มือดึงคำถามกับเกณฑ์คะแนนจากไฟล์เดียวกัน จึงตรงกับแอปเสมอ

`check-balance.mjs` ไล่ทุกเส้นทางคำตอบ (ตอนนี้ 12,000 เส้นทาง) แล้วรายงานว่าแต่ละสายมีโอกาสออกกี่เปอร์เซ็นต์
ปัจจุบัน **13.8–19.4%** (อุดมคติคือ 16.7%)

คะแนน normalize ด้วยเพดานของแต่ละแกนก่อนจัดอันดับเสมอ การเพิ่มตัวเลือกที่ให้คะแนนสายใดสายหนึ่ง
จึงไม่ทำให้สายนั้นได้เปรียบโดยอัตโนมัติ

> ถ้าเพิ่มข้อที่มีมากกว่า 6 ตัวเลือก ต้องทบทวนก่อน — ชูนิ้วได้สูงสุด 10 นิ้ว
> แต่เกิน 6 เริ่มนับยากและช้าที่บูธ
